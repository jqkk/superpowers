# diagnosing-superpowers — 슈퍼파워 세션 진단

> 원문: [`skills/diagnosing-superpowers/SKILL.md`](../../../skills/diagnosing-superpowers/SKILL.md)
> 트리거(원문 유지): `Use when a superpowers session went wrong and your human partner wants to know why — repeated work, ignored plans, stumbles, poor results, a skill that didn't fire, "it took too long", "why is it so expensive", "what is it doing" — or wants to build a bug report for the superpowers maintainers, for the current session or a past one identified by id or path, on any harness.`
> 이 문서는 사람이 읽기 위한 번역본입니다. 에이전트가 따르는 정본은 영어 원문입니다.

---

## 개요

세션에서 무엇이 잘못됐는지 사람 파트너와 함께 특정하고, 디스크의 트랜스크립트를 읽고, **증거와 함께 무슨 일이 있었는지 보고**한다. **보고할 뿐, superpowers를 진단하지 않는다.** 번들이나 이슈를 트리아지하는 쪽이 superpowers를 바꿀지 결정한다.

**핵심 원칙:** 모든 발견은 `path:line`을 인용한다. **인용이 없으면 발견이 아니다.** 모든 숫자는 트랜스크립트나 내가 실행한 명령에서 나오지, 기억에서 나오지 않는다.

## 워크플로

단계마다 todo를 만든다. 5~7단계는 명시된 조건에서만 실행된다.

1. **문제 인테이크.** 다음을 담은 진술을 쓸 수 있을 때까지 **한 번에 하나씩** 질문한다: 대상 세션, 알고 있다면 턴 범위, 파트너가 기대한 것, 실제로 일어난 것, 그리고 그들이 신경 쓰는 관측치(실제 시간, 토큰, 반복된 행동, 특정 행동 하나). **"너무 오래 걸렸어"는 불평이지 문제 진술이 아니다.** 목표가 superpowers 버그 리포트인지도 기록한다
2. **위치 확정.** `references/session-discovery.md`를 써서 각 세션을 **검증된 절대 파일시스템 경로**로 해소한다. 과거 세션은 첫 프롬프트와 타임스탬프를 인용해 확인하고, 기각한 모든 후보를 이유와 함께 나열하거나 "none"이라고 적는다. 서브에이전트 트랜스크립트를 열거한다. `~/.superpowers/diagnosing-superpowers/<session-id>/`를 만들고, 파트너에게 그 경로를 알려주고, `templates/case.md`를 거기 채운다 — 환경과 스킬 관찰에 대한 출처 규칙을 따른다
3. **트리아지.** 보고된 문제 주변 영역을 **내가 직접** 읽는다. 그다음 차원마다 분석가 서브에이전트 하나씩을 병렬로 파견한다. 각각에게 케이스 파일 경로, `prompts/analyst-common.md`, 그리고 `prompts/`의 차원 파일 하나를 준다: `skill-timeline.md`, `plan-adherence.md`, `repeated-work.md`, `stumbles.md`, `quality-evidence.md`, `request-conflicts.md`, `cost-and-time.md`. 트랜스크립트가 길면 차원을 턴 범위로 쪼갠다. **`path:line`이 없는 발견은 버린다**
4. **보고.** `templates/report.md`의 모든 섹션을 순서대로 채우고, 워크스페이스에 쓰고, 보여주고, 경로를 준다. 인용된 내용이 **실제로 무엇을 증명하는지** 점검하고 뒷받침 케이스를 보존한다. 심볼릭 링크 별칭은 중복 사본이 아니다
5. **GitHub 이슈** — 리포트 §7이 "가능함" 또는 "유력함"이라고 하거나 파트너가 요청할 때만. `references/github-issues.md`에 따라 증상으로 열린 이슈와 닫힌 이슈를 검색한다. 일치하는 것을 보여주고 가장 가까운 이슈에 리포트를 추가하자고 제안한다. 일치하는 것이 없으면 `templates/issue.md`를 채우고, 워크스페이스에 쓰고, **정확한 텍스트를 보여주고, 승인 후에만** 이슈를 만든다. `gh`는 파일을 첨부할 수 없다. 번들이 있으면 경로를 파트너에게 주어 브라우저에서 첨부하게 한다
6. **내보내기(Export)** — 파트너가 번들을 요청할 때만. **절대 요청 없이 만들지 않는다.** 인테이크 목표가 버그 리포트였다면, 스크럽된 번들을 요청 시 제공할 수 있다고 **한 번** 말하고 기다린다. 편집 수준을 묻되 각각 무엇을 포함하는지 밝힌다: skeleton(도구 결과 본문 없음), evidence(인용된 이벤트의 본문만), full. `templates/bundle-README.md`에 따라 번들을 만들고, `prompts/scrub.md`를 파견한 뒤 `prompts/scrub-audit.md`를 파견하며, 감사가 CLEAN을 반환할 때까지 둘을 반복한다. 최종 스크럽 로그, 파일 목록, 프라이버시·증거 결과를 보여주기 전에 번들 템플릿의 증거 점검과 대조를 완료한다. **승인 후에만** 아카이브(`zip -r` 또는 `tar -czf`)한다. 아카이브 경로와 함께, 무엇이 들어 있는지 말하고, 치환 내역은 스크럽 로그를 가리키고, **스크럽이 놓칠 수 있으므로 공유 전에 모든 파일을 직접 검토해야 한다**고 말한다
7. **유사 세션** — 요청받았을 때만. 확인된 발견을 시그니처로 바꾸고, mtime과 크기로 후보를 나열하고, 마커 줄 번호를 찾고, 후보마다 `prompts/similar-session.md`를 병렬로 파견하고, 리포트 §9에 덧붙인다

## 빠른 참조

**일곱 분석가는 항상 전부 돈다.** 이 표는 3단계에서 내가 직접 읽을 영역과 평결에서 앞세울 발견을 알려준다.

| 불평 | 먼저 읽고, 앞세울 것 |
|---|---|
| "너무 오래 걸렸어" | cost-and-time, stumbles |
| "왜 이 추가 작업을 한 거야?" | repeated-work, plan-adherence |
| "왜 이렇게 비싸?" | cost-and-time |
| "대체 뭘 하고 있는 거야?" (아직 실행 중) | skill-timeline; 진행 중임을 커버리지에 기록 |
| "계획을 무시했어" | plan-adherence, 컴팩션 줄 먼저 |
| "스킬 X가 안 떴어" | skill-timeline |

## 엄격한 규칙

- **컨텍스트 안전.** 트랜스크립트 한 줄이 1MB일 수 있다. 모든 세션 파일에, 매번 `references/context-safety.md`를 따른다
- **읽기 전용.** 세션 파일을 절대 수정·이동·삭제하지 않는다
- **서브에이전트에게는 정확한 경로를.** 서브에이전트의 "현재 세션"은 자기 것이다. 절대 경로와 id를 넘긴다
- **사람의 프롬프트만.** 훅 출력, 시스템 리마인더, 도구 결과는 파트너의 말이 아니다. 서브에이전트 트랜스크립트에서 "user"는 부모 에이전트다
- **superpowers 진단 금지.** 리포트 §7은 관여 여부를 진술하고 거기서 멈춘다. **스킬의 결함을 지목하거나 변경을 제안하지 않는다.** 파트너가 수정을 요구해도 이 규칙은 면제되지 않는다. 이슈 단계를 가리키고 요청 시 번들을 제공할 수 있다고 언급한다. 파트너에게 조언도 하지 않는다
- **승인 게이트.** 파트너가 스크럽 로그와 파일 목록을 보기 전에는 아카이브 없음. 정확한 텍스트를 승인하기 전에는 이슈나 코멘트 없음
- **분석 전에 인테이크.** 파트너가 답하기 전에는 2~7단계의 어떤 것도 시작하지 않는다. 그들이 자리에 없으면 질문을 써두고 멈춘다. **내가 재구성한 진술은 답이 아니다.** 이미 범위가 정해진 요청 — 특정 이벤트 하나, 지금 무엇이 돌고 있는지, 또는 어떤 분석을 돌릴지 — 은 그 자체가 진술이다. 그것에 답하고, 그다음 묻는다. 세션 전체에 대한 "왜"는 불평이다

## 위험 신호

| 생각 | 실제 |
|---|---|
| "문제가 뻔하니 인테이크는 건너뛰자" | 문제 진술이 모든 것의 범위를 정한다. 물어라. |
| "자리에 없으니 진술을 내가 재구성하자" | 그들이 원한 것을 재구성할 수 없다. 질문을 써두고 멈춰라. |
| "일단 전부 훑고 마지막에 묻자" | 범위 없는 훑기는 엉뚱한 질문에 그들의 예산을 쓴다. 먼저 물어라. |
| "버그 리포트를 원하니 번들을 지금 만들자" | 번들은 그들의 세션 데이터를 포장한 것이다. 요청할 때만 만들어라. |
| "작고 표적화된 수정이라 재구성은 불필요해" | 아무리 작아도 네가 판단할 일이 아니다. 증거를 보고하라. 트리아저가 결정한다. |
| "토큰당 가격은 잘 알려져 있잖아" | 트랜스크립트에서 계산하지 않은 숫자는 지어낸 것이다. 인용하거나 버려라. |
