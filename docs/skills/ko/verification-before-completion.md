# verification-before-completion — 완료 선언 전 검증

> 원문: [`skills/verification-before-completion/SKILL.md`](../../../skills/verification-before-completion/SKILL.md)
> 트리거(원문 유지): `Use when about to claim work is complete, fixed, or passing, before committing or creating PRs - requires running verification commands and confirming output before making any success claims; evidence before assertions always`
> 이 문서는 사람이 읽기 위한 번역본입니다. 에이전트가 따르는 정본은 영어 원문입니다.

---

## 개요

**핵심 원칙:** 주장보다 증거가 먼저, 항상.

**규칙의 문자를 어기는 것은 규칙의 정신을 어기는 것이다.**

## 철칙 (The Iron Law)

```
갓 얻은 검증 증거 없이는 완료를 주장할 수 없다
```

이번 메시지에서 검증 명령을 실행하지 않았다면, 통과한다고 주장할 수 없다.

## 게이트 함수

```
어떤 상태를 주장하거나 만족을 표현하기 전에:

1. 식별: 어떤 명령이 이 주장을 증명하는가?
2. 실행: 전체 명령을 새로, 완전하게 실행한다
3. 판독: 전체 출력을 읽고, 종료 코드를 확인하고, 실패 개수를 센다
4. 검증: 출력이 주장을 뒷받침하는가?
   - 아니면: 증거와 함께 실제 상태를 말한다
   - 맞으면: 증거와 함께 주장한다
5. 그제서야: 주장한다

한 단계라도 건너뛰면 = 검증이 아니라 거짓말
```

## 흔한 실패

| 주장 | 필요한 것 | 불충분한 것 |
|---|---|---|
| 테스트 통과 | 테스트 명령 출력: 실패 0 | 이전 실행 결과, "통과할 것임" |
| 린터 깨끗함 | 린터 출력: 에러 0 | 부분 검사, 추정 |
| 빌드 성공 | 빌드 명령: exit 0 | 린터 통과, 로그가 괜찮아 보임 |
| 버그 수정됨 | 원래 증상 테스트: 통과 | 코드를 바꿨으니 고쳐졌겠지 |
| 회귀 테스트 동작 | red-green 사이클 검증 완료 | 테스트가 한 번 통과함 |
| 에이전트 완료함 | VCS diff에 변경이 보임 | 에이전트가 "성공" 보고함 |
| 요구사항 충족 | 한 줄씩 체크리스트 대조 | 테스트 통과 |

## 위험 신호 — 멈출 것

- "should", "probably", "seems to" 같은 표현 사용
- 검증 전에 만족 표현 ("좋아요!", "완벽합니다!", "다 됐습니다!" 등)
- 검증 없이 커밋/푸시/PR 직전
- 에이전트의 성공 보고를 신뢰
- 부분 검증에 의존
- "이번 한 번만" 생각
- 피곤해서 일을 끝내고 싶음
- **검증을 실행하지 않고 성공을 암시하는 모든 표현**

## 합리화 차단

| 변명 | 실제 |
|---|---|
| "이제 될 거야" | 검증을 **실행**하라 |
| "확신해" | 확신 ≠ 증거 |
| "이번 한 번만" | 예외 없음 |
| "린터 통과했어" | 린터 ≠ 컴파일러 |
| "에이전트가 성공이라던데" | 독립적으로 검증하라 |
| "피곤해" | 피로 ≠ 면제 사유 |
| "부분 검사면 충분해" | 부분은 아무것도 증명하지 못한다 |
| "표현이 다르니 규칙이 적용 안 돼" | 문자보다 정신 |

## 핵심 패턴

**테스트:**
```
✅ [테스트 명령 실행] [확인: 34/34 통과] "모든 테스트 통과"
❌ "이제 통과할 겁니다" / "맞아 보입니다"
```

**회귀 테스트 (TDD Red-Green):**
```
✅ 작성 → 실행(통과) → 수정 되돌리기 → 실행(반드시 실패) → 복원 → 실행(통과)
❌ "회귀 테스트를 작성했습니다" (red-green 검증 없이)
```

**빌드:**
```
✅ [빌드 실행] [확인: exit 0] "빌드 통과"
❌ "린터 통과했습니다" (린터는 컴파일을 검사하지 않는다)
```

**요구사항:**
```
✅ 계획 재독 → 체크리스트 작성 → 항목별 검증 → 누락 또는 완료 보고
❌ "테스트 통과, 단계 완료"
```

**에이전트 위임:**
```
✅ 에이전트 성공 보고 → VCS diff 확인 → 변경 검증 → 실제 상태 보고
❌ 에이전트 보고를 신뢰
```

## 적용 시점

**다음 직전에는 항상:**
- 성공/완료 주장의 모든 변형
- 만족의 모든 표현
- 작업 상태에 대한 모든 긍정적 진술
- 커밋, PR 생성, 작업 완료
- 다음 태스크로 이동
- 에이전트에게 위임

**규칙이 적용되는 범위:**
- 정확한 문구
- 바꿔 말한 표현과 동의어
- 성공의 암시
- 완료/정확성을 시사하는 모든 의사소통
